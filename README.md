# wasapi-gapless-recorder

[English](README.en.md)

**مدخل: صوت النظام على ويندوز ← مخرج: مقاطع WAV متتالية بلا فجوة واحدة بينها.**

مسجّل يلتقط صوت السماعة نفسها (WASAPI loopback) وليس المايكروفون.
يقسّم التسجيل إلى ملفات WAV بطول ثابت، والانتقال بين الملفات بلا أي فقد.
قياس فعلي على هذا الجهاز: 334,848 إطاراً صوتياً متتابعاً في 4 ملفات،
وقفزة الموجة عند حدود الملفين 43 وحدة فقط من سقف نظري 692 — أي موجة متصلة.

## المشكلة

تسجيل محاضرة طويلة في ملف واحد يعطي ملفاً ضخماً لا يصلح للمعالجة أثناء التسجيل.
والتقسيم الساذج — إغلاق الجهاز وإعادة فتحه لكل مقطع — يُسقط إطارات عند كل حدّ.
النتيجة كلمات مقطوعة عند بداية كل ملف جديد.

## كيف يشتغل

| الملف | الأسطر | الدور |
|---|---|---|
| `audio_capture.py` | 219 | خيط الالتقاط وتقسيم المخازن عند الحدود |
| `shared_state.py` | 111 | حالة مشتركة آمنة للخيوط (13 قسم قفل) |
| `ui.py` | 506 | لوحة Tkinter حيّة تتحدث كل 500 مللي ثانية |
| `main.py` | 230 | الربط، ومعالجة غياب وحدة التفريغ الاختيارية |

آلية الالتقاط بالأرقام:

1. يُفتح مجرى WASAPI loopback مرة واحدة فقط طوال الجلسة.
2. كل قراءة تجلب 1024 إطاراً (نحو 21 مللي ثانية عند 48000 هرتز).
3. حدّ المقطع بالإطارات = التردد × مدة المقطع (48000 × 300 = 14,400,000).
4. حالة التسجيل تُحدَّث كل 0.1 ثانية، والواجهة تقرأها كل 500 مللي ثانية.
5. عند الإيقاف، يُحفظ المقطع الأخير الجزئي إن تجاوز حجمه ترويسة WAV (44 بايت).

## أهم قرار في التصميم

**المشكلة:** حدّ المقطع يقع غالباً في منتصف مخزن القراءة، لا عند نهايته.

**القرار:** التقسيم يحدث في طبقة الكتابة، لا في طبقة الالتقاط.
عندما يعبر مخزن 1024 إطاراً حدّ المقطع، يُقسم بالبايت الدقيق:
الجزء الأول يُكمل الملف الحالي ويغلقه، والجزء الثاني يفتتح الملف التالي فوراً.
الإطار الواحد = عدد القنوات × 2 بايت، فالحساب بالبايت لا بالتقريب الزمني.

**التكلفة:** حساب حدود يدوي دقيق بدل استدعاء مكتبة تقطيع جاهزة.
**العائد:** صفر إطار مفقود، والمجرى لا يُغلق ولا يُعاد فتحه أبداً بين المقاطع.

## إثبات مقيس أنه يعمل

تسجيل حقيقي لنغمة 440 هرتز، مقاطع بطول ثانيتين، على هذا الجهاز:

```
segment_0001.wav: frames=96000 rate=48000 ch=2 dur=2.0000s
segment_0002.wav: frames=96000 rate=48000 ch=2 dur=2.0000s
segment_0003.wav: frames=96000 rate=48000 ch=2 dur=2.0000s
segment_0004.wav: frames=46848 rate=48000 ch=2 dur=0.9760s
TOTAL frames=334848 = 6.9760s continuous audio
gapless boundary check (every full segment == rate*2 frames): True
```

وفحص اتصال الموجة عبر حدود الملفين الأول والثاني:

```
last 8 L-samples of seg1: (..., -2614, -2588, -2555)
first 8 L-samples of seg2: (-2512, -2461, -2401, ...)
delta ACROSS the file boundary: 43
theoretical max per-sample delta for 440Hz sine: 692
```

الموجة الجيبية تكمل مسارها عبر حدود الملفين كأنها ملف واحد.

## التشغيل

يعمل على ويندوز فقط (WASAPI خاص بويندوز).

```bash
pip install -r requirements.txt
python main.py --segment-seconds 300 --output-dir ./output
```

الإيقاف بإغلاق النافذة أو `Ctrl+C`، ويُحفظ المقطع الجزئي الأخير تلقائياً.
وحدة التفريغ النصي اختيارية: عند غياب `transcriber.py` يعمل التسجيل بشكل طبيعي.

## لماذا بنيته

أحتاج تسجيل محاضرات طويلة من صوت النظام على شكل مقاطع جاهزة للمعالجة الفورية.
التقسيم الساذج يفقد إطارات عند كل حدّ؛ هذا التصميم فقد 0 إطار في قياس 334,848 إطاراً.
