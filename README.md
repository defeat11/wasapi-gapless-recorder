# wasapi-gapless-recorder

[English](README.en.md)

**المدخل: صوت النظام على ويندوز ← المخرج: مقاطع WAV ورا بعض، ما بينها ولا فجوة.**

يسجّل الصوت الطالع من السماعة نفسها (WASAPI loopback)، مو من المايكروفون.
يقسّم التسجيل ملفات WAV بطول ثابت، والانتقال من ملف للي بعده ما يضيّع ولا إطار.
قِسته على هذا الجهاز: 334,848 إطار صوتي ورا بعض في 4 ملفات،
وقفزة الموجة عند حد الملفين 43 وحدة بس، والسقف النظري 692 — يعني الموجة متصلة.

## المشكلة

لو سجّلت محاضرة طويلة بملف واحد، يطلع لك ملف ضخم ما ينفع تعالجه وأنت لسه تسجّل.
والتقسيم البسيط — تسكّر الجهاز وتفتحه من جديد لكل مقطع — يضيّع إطارات عند كل حد.
النتيجة: كلمات مقطوعة في بداية كل ملف جديد.

## كيف يشتغل

| الملف | الأسطر | الدور |
|---|---|---|
| `audio_capture.py` | 219 | خيط الالتقاط، ويقسّم المخازن عند الحدود |
| `shared_state.py` | 111 | حالة مشتركة آمنة بين الخيوط (13 قسم قفل) |
| `ui.py` | 506 | لوحة Tkinter حيّة، تتحدث كل 500 مللي ثانية |
| `main.py` | 230 | يربط الأجزاء، ويشتغل عادي لو وحدة التفريغ مو موجودة |

الالتقاط بالأرقام:

1. مجرى WASAPI loopback يُفتح مرة وحدة بس طول الجلسة.
2. كل قراءة تجيب 1024 إطار (حوالي 21 مللي ثانية عند 48000 هرتز).
3. حد المقطع بالإطارات = التردد × مدة المقطع (48000 × 300 = 14,400,000).
4. حالة التسجيل تتحدث كل 0.1 ثانية، والواجهة تقراها كل 500 مللي ثانية.
5. عند الإيقاف، المقطع الأخير الناقص ينحفظ لو حجمه أكبر من ترويسة WAV (44 بايت).

## أهم قرار في التصميم

**المشكلة:** حد المقطع يجي غالباً في نص مخزن القراءة، مو عند نهايته.

**القرار:** التقسيم يصير في طبقة الكتابة، مو في طبقة الالتقاط.
لما يعدّي مخزن الـ 1024 إطار حدّ المقطع، أقسمه بالبايت بالضبط:
الجزء الأول يكمّل الملف الحالي ويسكّره، والجزء الثاني يبدأ الملف اللي بعده على طول.
الإطار الواحد = عدد القنوات × 2 بايت، فالحساب يصير بالبايت مو بتقريب زمني.

**التكلفة:** لازم أحسب الحدود بيدي بدقة بدل ما أستخدم مكتبة تقطيع جاهزة.
**العائد:** ولا إطار ضايع، والمجرى ما يتسكّر ولا يتفتح من جديد بين المقاطع.

## إثبات مقيس أنه يعمل

تسجيل حقيقي لنغمة 440 هرتز، كل مقطع ثانيتين، على هذا الجهاز:

```
segment_0001.wav: frames=96000 rate=48000 ch=2 dur=2.0000s
segment_0002.wav: frames=96000 rate=48000 ch=2 dur=2.0000s
segment_0003.wav: frames=96000 rate=48000 ch=2 dur=2.0000s
segment_0004.wav: frames=46848 rate=48000 ch=2 dur=0.9760s
TOTAL frames=334848 = 6.9760s continuous audio
gapless boundary check (every full segment == rate*2 frames): True
```

وهذا فحص اتصال الموجة عند حد الملف الأول والثاني:

```
last 8 L-samples of seg1: (..., -2614, -2588, -2555)
first 8 L-samples of seg2: (-2512, -2461, -2401, ...)
delta ACROSS the file boundary: 43
theoretical max per-sample delta for 440Hz sine: 692
```

الموجة تكمّل مسارها عبر حد الملفين كأنها ملف واحد.

## التشغيل

يشتغل على ويندوز بس (WASAPI خاص بويندوز).

```bash
pip install -r requirements.txt
python main.py --segment-seconds 300 --output-dir ./output
```

توقفه بإغلاق النافذة أو `Ctrl+C`، والمقطع الناقص الأخير ينحفظ لحاله.
وحدة التفريغ النصي اختيارية: لو `transcriber.py` مو موجود، التسجيل يشتغل عادي.

## لماذا بنيته

كنت أبي أسجّل محاضرات طويلة من صوت النظام، مقاطع جاهزة أعالجها على طول.
التقسيم البسيط يضيّع إطارات عند كل حد؛ هذا التصميم ضيّع 0 إطار في قياس 334,848 إطار.
